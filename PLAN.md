# PLAN — "Steal a Snackling" (working title)

> Buy wacky collectible Snacklings off a conveyor belt, place them in your base where they earn cash every
> second, protect your base — and sneak into other players' bases to steal their best ones.

This document is the build plan for round 1 (playable MVP). It lists the systems, every module, every remote,
the save schema and the order things are built in. Decisions that would be expensive to reverse are recorded
separately in [`DECISIONS.md`](DECISIONS.md); the economy curve is explained in [`BALANCE.md`](BALANCE.md).

---

## 1. Architecture in one picture

```
┌──────────────────────────── ReplicatedStorage.Shared ────────────────────────────┐
│ Config/   plain-data modules (names, colours, prices, timers, IDs)  ← re-theme / │
│           balance / LiveOps are data changes                                     │
│ Logic/    PURE modules: no Roblox services, no requires. Config is passed in.    │
│           Unit-tested with Lune in CI.                                           │
│ Net, CreatureVisuals, UiTheme   thin Roblox helpers used by both sides           │
└──────────────────────────────────────────────────────────────────────────────────┘
          ▲ require (instance paths)                       ▲
┌─────────┴───────── ServerScriptService.Server ─────┐  ┌──┴──── StarterPlayerScripts.Client ───┐
│ Services: thin Roblox layer that owns state,       │  │ Controllers: render state, build UI,  │
│ validates every intent, calls Logic for decisions  │  │ create local ProximityPrompts, send   │
│                                                    │  │ INTENTS only ("buy item 17")          │
└────────────────────────────────────────────────────┘  └───────────────────────────────────────┘
```

* **Server-authoritative.** Clients send intents through RemoteEvents. Every remote passes through
  `Remotes.onIntent`: per-player token-bucket rate limit → `pcall` → handler, which validates every argument
  with `Logic/Guard`. Handlers re-derive
  prices, rarities and positions from server state; nothing numeric from the client is trusted.
* **Pure logic has no Roblox dependencies.** `src/shared/Logic/*` and `src/shared/Config/*` never touch
  `game`, `Instance`, `Vector3`, `Color3`, `os.clock` etc. Clocks and RNGs are passed in. They only require
  each other and `Types.luau` with relative string requires (`require("../Types")`), which Roblox and Lune
  resolve identically. That is what lets Lune load them directly in CI (see DECISIONS.md).
* **World built in code.** The map (8 plots, conveyor, lobby, leaderboards) is generated by
  `MapBuilder` at server start, so the repo syncs into an empty Baseplate and plot geometry is data
  (`Config/Gameplay.luau → plot`).

### `src/shared` (Roblox helpers, not unit-tested)
`Net` (create/get remotes by name), `GameData` (catalogue built once from config; `price` / `income` /

### `src/server`
`init.server.luau` bootstraps in order:
`Remotes → DataService → MapThemeService.firstMap → MapBuilder (+ SceneryBuilder, WorldLighting) → PlotService → Analytics →
LiveOpsService → SeasonService → MapThemeService → ModifierService → Replication → PositionTracker → EconomyService →
BeltService →
LockService → StealService → RebirthService → MonetizationService → RetentionService → SocialService →
TutorialService → SnackdexService → QuestService → LeaderboardService → SettingsService → DevCommands →
PlayerLifecycle`, and wires cross-service join/leave steps through `PlayerLifecycle.hooks()` (keeps services free of

`PlayerLifecycle` owns join/leave ordering: load profile → assign plot → check passes → offline earnings →
spawn creatures → send initial state; on leave: cancel steals involving the player → auto-collect stored cash →
release plot → release profile.

## 4. Remotes (all in `ReplicatedStorage.Remotes`, created by the server)

Client → server **intents** (each rate-limited and argument-guarded; limits live in `Config/Gameplay.rateLimits`):

| Remote | Args | Server validation |
| --- | --- | --- |
| `ClientReady` | – | once per session |
| `BuyBeltItem` | `itemId: int` | item exists, not sold, within buy range of *computed* belt position, cash ≥ server price, free podium |
| `BuyPodium` | – | inside own plot, below cap, cash ≥ server cost |
| `SellCreature` | `podium: int` | own podium, creature present, not being stolen, near podium |
| `StealBegin` | `plot: int, podium: int` | starts the server-side hold timer if `StealRules.canBeginHold` (at the podium, inside the base, position trusted) |
| `StealConfirm` | `plot: int, podium: int` | hold time elapsed, `StealRules.canGrab` (lock, grace, range, inside the base no higher than a jump above its walls (`grabJumpAllowance`), position trusted, own free podium, not carrying) |
| `TagThief` | `userId: int` | target is carrying, within tag reach (horizontal range + vertical allowance), tag cooldown, tagger's position trusted (`PositionTracker`) |
| `LockBase` | – | owner, near lock button, `LockRules` (cooldown, or a lock token) |
| `Rebirth` | – | `RebirthMath.canRebirth` |
| `ClaimDaily` | – | `DailyStreak.canClaim` |
| `ClientEvent` | `name: string` | whitelist (`store_opened`, `store_product_clicked`) → analytics |
| `CheckGroup` | – | group feature on, at most once per 10 s, not already checking → re-check membership (`IsInGroupAsync`, then `GetGroupsAsync`) |
| `InvitePrompted` | – | analytics only (`invite_prompt_opened`); nothing is rewarded for inviting |
| `SkipTutorial` | – | a tutorial is running → it ends with no reward (steps themselves only finish from gameplay the server saw) |
| `SetSetting` | `key: string, on: boolean` | key is a known setting (`SettingsRules.KEYS`), value a boolean → `settings_<key>` flag |
| `ClaimQuest` | `slot: int` | today's quest `slot` is finished and not claimed (`QuestRules.claim`; a stale day is paid automatically instead) |
| `VoteMap` | `themeId: string` | a map vote is running and `themeId` is on its ballot (one vote per player, changeable) |
| `CrateBegin` | `crateId: int` | the supply crate exists, has landed and is closed; the player's trusted position is within reach → the hold starts |
| `CrateOpen` | `crateId: int` | same, and the hold lasted long enough (`DropRules.holdLongEnough`); the first one wins |
| `ClaimGift` | `index: int` | the gift exists, today's playtime unlocked it and it isn't claimed yet (`GiftRules.claim`) |
| `Spin` | – | a free spin is ready or one is banked (`SpinRules.source`), and the last reel has finished |
| `GetAchievements` | – | rate limit only → `AchievementSync` with the player's progress |
| `RedeemCode` | `code: string` | letters and digits, at most 24 (`CodeRules.normalize`); the code exists, has not expired and its `code_<CODE>` flag is unset; a Snackling code needs a free podium; rate limit 3 then 1 per 5 s |
| `DevGrantProduct` | `key: string` | **Studio only** – runs the real receipt path with a fake receipt |

(mutation and multipliers included), `BeingStolen`; player `Carrying`, `VIP`. Rainbow parts carry the

luck next changes), `PurchasedLuckEndsAt`, `CashMultiplier`, `ActiveEventIds`, `EventBanner`, `EventBannerId`,

## 5. Data schema (version 4)

```lua
type CreatureRecord = { uid: string, id: string, podium: number, acquiredAt: number, stored: number,
                        variant: string? } -- variant = mutation id (Config/Mutations), nil = plain
type PurchaseRecord = { purchaseId: string, productId: number, key: string, robux: number, at: number }
type PlayerData = {   -- exactly Types.PlayerData
    version: number,             -- schema version for migrate()
    cash: number,
    creatures: { CreatureRecord }, -- what sits on podiums (`stored` = uncollected cash on that podium)
    quarantine: { CreatureRecord }, -- kept off the podiums (unknown id, or no free podium); restored later (v2)
    nextUid: number,             -- per-player creature uid counter
    podiumUpgrades: number,      -- bought with cash (pass bonus is not saved, it is checked live)
    rebirths: number,
    rebirthMultiplier: number,   -- stored at rebirth time (non-retroactive balance, DECISIONS #12)
    lockTokens: number,          -- from "Instant Base Lock" product
    lockTimers: { cooldownUntil: number, vulnerableUntil: number }, -- os.time; survive leaving (v2)
    processedReceipts: { string },  -- bounded ring of PurchaseIds (idempotency)
    cashPackQuotes: { { purchaseId: string, amount: number } }, -- pack amount fixed at first sight (v2)
    purchaseHistory: { PurchaseRecord }, -- bounded
    daily: { streak: number, lastClaimDay: number },
    stats: { steals: number, timesStolenFrom: number, beltPurchases: number, playTime: number,
             bestCashPerSecond: number, robuxSpent: number, totalEarned: number },
    flags: { [string]: boolean },  -- onboarding funnel milestones, one-time rewards (`social_groupWelcome`),
                                   -- tutorial progress (`tutorial_<step>`, `tutorial_done`), settings (`settings_<key>`),
                                   -- redeemed codes (`code_<CODE>`), achievements paid (`ach_<id>`),
                                   -- maps played on (`map_<id>`), achievement milestones (`did_<id>`)
    firstJoin: number, lastSeen: number,
    gifts: { day: number, seconds: number, claimed: { number } },  -- playtime gifts today (v4)
    spin: { nextFreeAt: number, spins: number, total: number },     -- the Lucky Spin (v4)
    snackdex: { creatures: { [string]: boolean },              -- ever owned (v3, backfilled on migration)
                variants: { [string]: { [string]: boolean } }, -- creature id -> mutation ids owned with it
                tiers: { [string]: boolean } },                -- rarity tiers whose reward was paid
    quests: { day: number, list: { { id: string, target: number, progress: number, claimed: boolean } },
              bonusClaimed: boolean },                         -- today's quests (v3)
}
```

## 6. Build order (each step = a commit)

2. Config data + pure Logic modules + Lune test runner and tests.
3. Core loop: Net/RemoteGateway, DataService (ProfileStore), MapBuilder, PlotService, BeltService,
   EconomyService, ReplicationService, client HUD/belt/prompts → **join → base → buy → earn → collect → save/load**.
4. Stealing + tagging + carry, base lock + grace period.
5. Rebirth.
6. Monetisation (passes, products, idempotent receipts, store UI, Studio dev purchases).
7. Retention (offline earnings popup, daily streak, leaderboards), announcements, LiveOps, analytics.
8. Balance simulation (`tools/simulate.luau`) → `BALANCE.md`; `DECISIONS.md`; quality gates clean; PR.

## 7. Out of scope this round (but not blocked)

Trading (creatures have stable `uid`s and live in one list → a trade is two `Inventory` moves), battle pass,
private servers, extra maps (plot geometry is data), custom models/sounds (`CreatureModels` folder + `Config/Sounds`),
animated seasonal props (decorations are static anchored parts; a client controller could bob the bats / ghosts).

## 8. Seasonal events (Halloween 2026, Winter 2026, Valentine's 2027, Easter 2027)

One LiveOps event id drives everything (DECISIONS.md #20): `Halloween2026` in `Config/LiveOps` (dates, banner,
countdown title) gates four event Snacklings (`eventId` in `Config/Creatures`), the Haunted mutation (`eventId` in
`Config/Mutations`) and the `halloween` seasonal theme (`Config/Seasons`), and `HalloweenLuck2026` adds a 2× luck
weekend. `LiveOpsService` re-evaluates active events every second and tells `SeasonService` when the set changes;
`SeasonService` builds or removes the theme's decorations (`Logic/SeasonRules.layout`) and fades the lighting in or
back. The HUD shows the banner with "Halloween ends in 3d 4h" and event Snacklings carry an "EVENT" tag. Balance:
BALANCE.md "Halloween". Studio: `/event Halloween2026 [minutes]`, `/event off`, `/spawn <eventCreature> haunted`.

`Winter2026` (18 Dec–4 Jan) is the second (DECISIONS.md #37): Peppermint Puffin, Candy Cane Chameleon, Yule Log Yak
and Spun Sugar Stag (hand-built polished models, `art/snackling-parts/batch-4.json`), the Festive mutation (a
pine-green knit look with twinkling fairy-light particles), and the `winter` theme: wrapped presents by every

## 9. First-time tutorial

A brand-new player learns the loop in about a minute (DECISIONS.md #21): **buy** a Snackling from the belt → **collect**
its cash from the glowing pad → **lock** the base → **steal** from another base. Each step is one short line in a
banner right under the cash (step badge "1/4", Skip button) and a 3D guide: a pulsing beam from the player's feet, a
bouncing arrow over the target and a highlight on it (nearest affordable belt item, the pad with the most cash, the
lock button; the steal step only shows a tip about the new-player shield). `TutorialService` finishes a step only when
the server applies that action (belt purchase, pad collect, lock, delivered steal); the lock step moves on after 20 s
of the lock being unavailable (or 60 s), the steal step after 90 s. Completing it pays $500 once per account
(`Config/Tutorial.reward`); Skip pays nothing; players who already had progress when it shipped never see it.
Progress lives in `data.flags` (no schema bump). Studio: `/tutorial` starts it again.

## 10. Snackdex and daily quests

Two "come back tomorrow" loops (DECISIONS.md #24), both server-authoritative and data-driven:

* **Snackdex** — every Snackling a player ever owns, and every mutation of it, is recorded (`SnackdexService`, on each
  `acquired` gameplay event: belt purchases, delivered steals, any other way one lands in a base; older saves are
  backfilled by the v3 migration). Owning every regular Snackling of a rarity tier completes it: a one-time cash reward
  (steady income, like a cash pack) and +3% permanent income (capped at +21%), claimed automatically with a banner.
  Event Snacklings have their own section and never block a tier. UI: Snackdex button → rarity tabs with X/Y, 3D
  preview cards (silhouettes for the undiscovered), NEW! toasts and badge dots.
* **Daily quests** — three a day (2 easy + 1 hard) from `Config/Quests`, rolled from the UserId and UTC day, counting
  only what the server saw (buy, collect from pads, sell, lock, steal, discover). Rewards and a bonus for all three are
  sized from steady income; claimed in the Rewards panel's Quests tab, or paid automatically at the day change.
* Studio: `/quests reset` re-rolls today's quests; `/dex fill <rarity|event>` discovers all but one Snackling of a
  section so completion is one purchase away.

## 11. Map themes

Twenty-three dressings of the same map (DECISIONS.md #29, #32, #38, #39, #45): Sunny Meadow, Candy Kingdom, Frosty
